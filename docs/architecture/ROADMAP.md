# Архитектура: разбор и план улучшений

Дата исходного разбора: 17 ноября 2026 года. Оценка сделана по текущим
исходникам, без испытаний на оборудовании. Это рабочий список: при каждом
исправлении обновляем статус, результат и проверку. Пункты ниже — направления
работы, а не утверждение, что каждый описанный риск уже воспроизведён.

## Что сохраняем

- Общую кодовую базу Standard / Ilim / Ski и централизованный BuildVariant.
- Разделение Scenario / Runner / Algorithm / Analyzer.
- Общие входные данные отчётов и снимки данных перед фоновой генерацией.
- Версионированные миграции, резервные копии и снимки карточек сессий.
- Учёт ручных исправлений отдельно от рассчитанных значений.
- Документацию формул и тесты анализаторов на известных зависимостях.

## План

1. **Границы слоёв — в работе; прямые зависимости от UI устранены.**
   Domain и Report включали SelectTests.h, сценарии и хранилища использовали
   типы из Widgets, Report::Saver сериализовал живой ChartView. См. результат
   первого шага ниже. Дальнейшее улучшение: заменить команды отображения
   в Program / AbstractScenario событиями испытаний и формировать графики
   в прикладном/презентационном слое. Перемещение типов само по себе
   не устраняет эту смысловую связанность.
2. **Разгрузить MainWindow и HistoryPresenter — запланировано.**
   Выделить координацию завершения испытания и сохранения его результатов
   в прикладной сервис. Окно отображает состояние и передаёт действия оператора.
3. **Упростить управление состоянием и потоками — запланировано.**
   Постепенно убрать вложенные QEventLoop из последовательностей испытаний.
   Проверить остановку в ожидании, потерю связи и закрытие во время отчёта;
   явно описать состояния и допустимые переходы.
4. **Различать вычисленный ноль и отсутствие результата — исправлено для Main/Pass|Fail.**
   Неудачные и отключённые расчёты основного теста дают NaN, а не ноль.
   Допуск требует конечных измерений и границ; отсутствующие данные дают
   Unknown. Интерфейс/отчёты показывают прочерк, БД хранит NULL.
   См. результат шага 4 ниже. Целочисленные результаты времени других тестов
   пока сохраняют собственный контракт (например, T_value=0 отображается
   как ошибка), их модель не менялась в этом шаге.
5. **Показывать ошибки сохранения — запланировано.**
   Не прерывать управление оборудованием из-за БД, но явно сообщать оператору,
   что результат не записан. Проверять возвращаемые значения HistoryWriter.
6. **Расширить постоянные проверки — запланировано.**
   Добавить миграции, импорт/откат, остановку, потерю связи и согласованность
   сохранённых результатов. Полезные экспериментальные стенды переводить
   в повторяемые проверки. Хранить версию методики расчёта вместе с результатом:
   смысл поля линейности менялся, старые значения требуют контекста методики.

## Шаг 1: зависимости от окон и виджетов

- Программа испытаний перенесена из SelectTests в Domain/Tests/Pattern.h.
  Числовые значения перечисления и строковые ключи истории сохраняются.
- ChartType и Point принадлежат Shared/Chart, библиотеке SharedData на QtCore.
  Widgets предоставляет только совместимые имена этих же типов, без копий.
- Domain, Report и Storage используют общие контракты напрямую и не включают
  заголовки Gui/Widgets. Имена графиков, поля точек и метатипы сохраняются.
- Report::Saver получает изображение и готовый QByteArray. ChartView
  сериализуется в GUI тем же QDataStream::Qt_6_2, формат .data не меняется.
- Чтение QLineEdit вынесено из NumberUtils в Gui/NumberInput; настройки
  устройства используют QCoreApplication вместо QApplication.
- StyledMessageBox, UiText, фабрика валидаторов и заголовки UI-shortcuts
  исключены из исходников Domain и собираются в Gui.
- Domain больше не линкует QtCharts. QtGui пока нужен из-за QImage/QColor
  в хранилищах снимков; отделение инфраструктуры хранения — отдельный шаг.
- Report не зависит от окон приложения; QtRPT по-прежнему использует QtWidgets
  как собственную зависимость движка PDF. Это не полноценная headless-архитектура.

Проверки: ArchitectureLayerIncludes запрещает UI-заголовки в нижних слоях;
SaverDataTests линкует Report без Gui и проверяет сохранение байтов .data
и изображения.

## Шаг 4: достоверность основного теста и Pass/Fail

Контракт числового показателя Main::Result: конечное число, включая 0, —
вычисленное значение; NaN — показатель не вычислен. Отдельного общего флага
valid на весь тест нет: например, регрессии могут быть доступны, а для
динамической ошибки не хватать общих участков ходов, либо для силы трения
не задан диаметр привода. Каждый показатель проверяется отдельно.

- По умолчанию показатели Main::Result неопределены. Ранний выход,
  вырожденные расчёты и недостаток данных не подставляют нули.
- Analyzer отклоняет как NaN, так и бесконечные входные отсчёты. Сила трения
  требует конечного положительного диаметра. Выключенная линейность
  остаётся неопределённой.
- CrossingStatusUpdater сбрасывает прежний результат перед пересчётом,
  проверяет конечность факта и обеих границ. Пружина получает Ok
  только при наличии обеих рассчитанных границ; известное нарушение даёт
  Fail даже при отсутствии второй границы, иначе неполные данные дают Unknown. Telemetry::clearAll также
  сбрасывает допуски, чтобы не сохранять прежний зелёный статус.
- Неизвестный факт не мешает сохранить известные нормативные границы.
  Unknown отличается от Ok отдельным State, а не значением поля miss.
- Нечисловой/пустой текст допуска динамической ошибки даёт NaN, а не 0.
  Записанный пользователем нулевой допуск остаётся допустимым числом.
- GUI показывает «--», оба Excel-пути и PDF — «—». Общий NumberFormat
  задаёт одинаковую обработку отсутствующих чисел и диапазонов в отчётах.
- HistoryWriter записывает любые неконечные числа как NULL; неопределённый
  допуск записывается со state='unknown'. Изменение схемы БД не требуется.

Проверки шага 4: MainValidityTests покрывает отсутствующие/бесконечные значения
и границы, настоящий вычисленный ноль, частичные данные пружины,
отсутствующие общие участки для динамической ошибки, сброс статуса,
разбор допуска и запись Unknown/NULL в изолированную временную SQLite.
MainResultPresentationTests проверяет тексты настоящих виджетов, источник
данных PDF и ячейки сгенерированного XLSX: прочерк отличается от 0.00.
Существующие тесты анализатора обновлены под новый контракт.

Ограничение: старые нули и вердикты в истории не переписываются автоматически.
Без исходных измерений нельзя достоверно восстановить смысл прежнего нуля.
Повторный анализ архивных графиков использует новый контракт, а существующие
строки истории сохраняют записанные ранее данные.

Финальная проверка шага 4: сборка Ilim с выключенными экспериментальными
модулями; CTest 5/5 успешно, VerifyReport завершается успешно. Ski с
включёнными экспериментальными модулями также собирался и проходил проверки
во время реализации. Для новой модели проверялись временные БД и файлы,
рабочая история не изменялась. Испытания на оборудовании не проводились.
