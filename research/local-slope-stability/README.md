Дата начала: 17 ноября 2026 года.

Разобраны [два реальных случая сильного изменения результата](results/explanations/report.md): нормировка на почти нулевой общий наклон и исчезновение худшего окна после прореживания. Это объяснение выбранных крайних случаев, а не оценка распространённости проблем. Воспроизведение: `OPENBLAS_NUM_THREADS=1 python3 research/local-slope-stability/scripts/explain_cases.py`.

**Архивный эксперимент:** [сводный отчёт по реальным записям](results/archive01/report.md). Реестр всех файлов и причин исключения — `results/archive01/inventory.csv`, базовые показатели — `baseline.csv`, варианты расчётов — `sensitivity.csv`, сводка по записям — `per_record_decimation.csv`. Запуск: `OPENBLAS_NUM_THREADS=1 python3 research/local-slope-stability/scripts/archive_study.py` (нужен NumPy). Исходный архив не изменяется. Предварительные критерии включения проверяют формат и вычислимость; техническую полноту испытания и независимость устройств они не подтверждают.

**Обновление 18 ноября:** [проверка исходного файла](05_Проверка_исходного_примера.md) подтвердила точное совпадение CSV и `.data`, но выявила конфликт единиц: `deg` в исходном графике и «мм» в учебных материалах. Старые материалы в `results/` сохраняются как первоначальный расчёт с неподтверждёнными подписями; актуальная проверка и результаты находятся в `results/stage01/`.

Рабочая тема: **«Исследование устойчивости показателей локальной крутизны характеристики трубопроводной арматуры по данным стендовых испытаний»**.

Сначала читаем [первое объяснение](01_Что_мы_считаем.md), затем [описание алгоритма](02_Алгоритм.md). План исследования находится в [отдельном файле](03_План_исследования.md). Для разговора с директором подготовлена [краткая записка](04_Для_обсуждения.md).

## Границы работы

Исследуем, насколько число зависит от ширины расчётного участка, плотности измерений, границ рабочего диапазона и возмущений данных. Повторяемость между независимыми прогонами проверим только после подтверждения, что испытания относятся к одному устройству без вмешательства и выполнены в сопоставимых условиях.

На этом этапе не устанавливаем диагноз, не назначаем допуск и не делаем выводов об исправности привода. Устойчивость алгоритма необходима, но сама по себе не доказывает диагностическую полезность.

## Первый пример

Использованы две существующие CSV-выгрузки PV-2223 из учебных материалов. Исходные файлы не изменяются. Связь с исходным испытанием 03.10.2024 указана в `docs/formulas/main_test.md`; перед включением результатов в статью требуется проверить выгрузки по исходным `.data` и единицы по метаданным.

Результаты первого запуска находятся в `results/`: `pilot.md` — читаемая сводка, `baseline.json` — расчёт и происхождение данных, `windows.csv` — локальные наклоны, `sensitivity.csv` — пробные изменения настроек и прореживание. Если запрошен рисунок, он сохраняется как `lesson.png`.

Запуск из корня репозитория:

```bash
python3 research/local-slope-stability/scripts/pilot.py
```

Для рисунка (нужен matplotlib):

```bash
MPLCONFIGDIR=/tmp/mpi-slope-matplotlib python3 research/local-slope-stability/scripts/pilot.py --plot
```

Можно указать другие файлы через `--forward`, `--backward` и другой каталог результатов через `--out`. CSV должен иметь колонки `x,y`, где x — давление, y — положение. Направления задаёт пользователь; программа не угадывает их по имени.

Это исследовательская реализация формул из текущего C++-кода, а не доказанный эквивалент всего приложения. Проверки на искусственных данных входят в запуск; побитовое совпадение с C++ не проверено. Приложение и его расчёты не изменены.
